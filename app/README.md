# 工作台：尚未接通

`v0.2.0-alpha.2` 是整理后的开发快照，工作台能力与 alpha.1 相同。**这个目录还没有启动命令、HTTP 服务或可上传照片的界面。** 现在可使用的是根目录的 Codex Skill，以及 `docs/` 下的静态示例；示例不是实际评图服务。

## 已写入的基础

| 位置 | 已有内容 | 尚不能代表什么 |
|---|---|---|
| `core/contracts.py` | 从现有 Skill 读取规则；校验点评、八维评分和调整参数 | 不代表不同模型已经达到同样的点评质量 |
| `core/provider.py` | 可注入传输的 Responses 协议适配；基本地址、大小和错误处理约束 | 未进行真实 API、模型或供应商兼容性验收 |
| `core/images.py` | 图片解码、预览、受限亮暗／颜色处理及可选裁切 | 未接入自动评图、保真复核或完整编辑流程 |
| `app/` | 包占位、Pillow 依赖和本说明 | 不是可运行应用 |

离线基础检查：在仓库根目录、虚拟环境中安装 `app/requirements.txt`，运行：

```bash
python3 -m unittest discover -s scripts -p 'test_workbench_core.py'
```

测试只使用模拟响应与合成小图，不发起真实模型请求、不产生 API 费用。调色模块测试仅证明文件和像素确实变化、原图文件保留，不证明调整好看。

## 还缺什么

本地服务、配置与上传界面、任务编排、取消与恢复、围绕照片追问、参考检索与核验、后期复核、历史记录和端到端验收均未完成。不要将这些模块直接作为公网服务部署。

真实调用需要使用者自己的模型服务配置，并可能产生费用；本快照没有保存任何密钥。未来的私人照片、记录和衍生图必须保存在仓库外，服务层的访问与存储保护仍待实现。完整范围见[双入口计划](../docs/dual-entry-plan.md)。
