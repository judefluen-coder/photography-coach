# 摄影教练：一个项目，两种使用入口

2026-10-19 · 根据用户对可视化交付的纠正更新。本文是当前范围依据，取代“只升级 Skill 展示页”的范围约定；不是功能完成声明。用户随后授权将截至当前的内容提交、推送并更新版本，因此以 `v0.2.0-alpha.1` 发布开发快照；这不代表双入口已完成，也不授权付费模型调用或新建托管服务。

## 产品是什么

Photography Coach 是摄影教练项目，Skill 是一种使用方式，不是整个产品。另一种方式是可实际使用的摄影工作台：用户在界面里上传自己的照片、获得针对这张照片的反馈、继续讨论、看调整对照，不需要先回到 Codex 生成报告再导入。

| 入口 | 用户怎么使用 | 当前状态 |
|---|---|---|
| Codex Skill | 在自己的 Codex 中附图，调用 `$photography-coach`，继续对话或生成报告 | 已有，保留安装与调用兼容 |
| 可视化工作台 | 启动项目界面，选择照片，获得真实点评、追问、调整和历史记录 | 尚未实现；静态示例不能替代 |
| GitHub 项目首页与示例 | 理解产品、选择使用方式、预览公开案例 | 已有展示层，辅助上述两种入口 |

快照另包含 `core/` 的规则装配、输出校验、模型协议适配和确定性后期实验模块，以及 `app/` 的包占位和依赖。它们只有离线单元测试，尚无服务路由、工作台界面与完整流程，详见[实现状态](../app/README.md)。

第一版按本地运行的 Web 工作台规划，不默认建设维护者付费提供模型的公共服务。用户已确认界面不依赖 Codex：下载项目、启动界面、配置自己的模型 API 后使用。Skill 入口继续使用 Codex 环境。

## 核对过的 GitHub 实例

以下为仓库文档和源码核查，未安装或实测这些第三方项目，也不构成安全或效果背书。

- [PaperBanana](https://github.com/dwzhu-pku/PaperBanana)：同仓库有实际生成／修改图片的 Web 界面与 `skill/` 入口。[界面代码](https://github.com/dwzhu-pku/PaperBanana/blob/main/app.py)和 [Skill 运行入口](https://github.com/dwzhu-pku/PaperBanana/blob/main/skill/run.py)都使用 `PaperVizProcessor`。借鉴“产品能力共用、入口不同”，不照搬其多 Agent 流程或生成式修图方式。
- [AnyBot](https://github.com/1935417243/AnyBot)：文档描述 Web 上传图片、继续会话、选择 Skill，并通过 Provider 连接 Codex 等运行环境。借鉴界面能够发起实际工作，不只是展示已有答案；不把摄影教练扩成通用 Agent 管理器。
- [Codex App Server 官方文档](https://learn.chatgpt.com/docs/app-server)：提供本地图片输入、显式 Skill 输入、会话与流式事件。可以作为可视化入口的候选运行适配器；这不是已完成的兼容性测试，也不意味着免费、无限额度或可以直接作为公众后台。

## 运行方式：已选择 A

| 方案 | 好处 | 代价与边界 |
|---|---|---|
| A. 界面独立运行，用户配置自己的模型 API（建议） | 没有 Codex 的摄影爱好者也能使用；Skill 仍走 Codex，不强迫原用户再配 API | 需要实现模型、检索与工具执行；供应商、模型、图片能力和费用需分别验证。密钥只交给本机服务，不写入前端包、仓库或日志 |
| B. 界面连接本机 Codex | 可沿用本地运行环境，较容易保持现有 Skill 工作流 | 仍需安装和登录 Codex；使用用户自己的额度／计费，不是面向所有人的免配置网站 |

不为兼容所有平台同时开发两套运行后端。首版实现 A，暂不开发 B；接口保留替换能力。未授权前不发起付费调用，不启动新的模型评测任务。

## 共用什么，而不是复制什么

1. **规则与知识**：现有 `references/` 仍是评价标准、评分、观察完整性、参考匹配及版权边界的来源。Skill 与工作台均引用同一版本；不能为网页另写一段泛化提示词就宣称等价。
2. **结果与处理合同**：共用点评、八维评分、位置、具体作品、练习与图片版本的字段和校验。将当前脚本中的可复用校验逐步提取，旧报告继续兼容。
3. **运行适配器**：负责图像输入、上下文、模型／工具调用、取消和失败处理。相同规则不保证不同模型输出完全相同，必须分别验证，不把文字相同当作质量相同。
4. **结果呈现**：已有滑动对照、图上定位、评分和下载作为工作台结果视图复用；便携 HTML 保留为导出物。首页只是介绍页，不再作为产品使用界面的交付。

首轮保留根目录 `SKILL.md`、`references/` 与既有安装方式，不为了目录整齐搬走整个 Skill。拟新增 `app/` 放工作台与本地服务，`core/` 放实际需要共用的合同和运行逻辑；只有确有共用需求才提取代码。

## 最小可用工作台

- **开始**：选图／拖入、预览、可选补充文字、开始点评。拍摄意图不是必填；上传前能看见模型连接与数据去向。
- **看片**：先显示一处成立关系和首要判断，展开查看全画面观察、八维评分、位置与具体参考；不替换成一段聊天长文。
- **讨论**：围绕当前图追问、指出错认或表达偏好；保留旧判断，说明修订依据。
- **调整**：真实原图／仅调色／有必要时裁切＋调色，能对照和下载。解释改善与代价；失败明确显示，不能用原图副本或只裁切冒充调色。
- **回来继续**：本机保存照片会话、刷新恢复、导出与删除；再上传时可主动关联上次问题，不自动给所有照片排名。

先保留上述闭环，不加账号体系、支付、社区、课程闯关、排行榜、多 Agent 管理台或公开托管。照片、密钥和私人记录不进入项目仓库；本地保存不等于模型处理全离线。

| 阶段 | 交付与验收 | 确认点 |
|---|---|---|
| 0. 纠正范围 | 记录双入口目标、实例依据、现状与缺口 | 已确认独立 API 方案，不依赖 Codex |
| 1. 真照片到真点评 | 工作台选图、实际模型请求、进度／取消／失败、针对该图的完整结果；开发测试替身必须标注且不混入真实模式 | 用非固定样例验证，不以静态页面验收代替；真实调用的账户与支出边界另确认 |
| 2. 在界面里继续 | 当前图追问与更正、实际调整对照、具体作品参考、保存与恢复 | 用户直接操作，不要求手工运行 Skill 或搬运 JSON；确认调色不是仅裁切 |
| 3. 双入口验收 | 原 Skill 可继续使用；工作台可独立走通所选运行方式；共享字段、规则版本与有限新图检查有记录 | 当前开发快照已获发布授权，不能据此宣称工作台验收通过；摄影质量门槛与工程可用性分开报告 |

主要修改位置：`app/`、必要的 `core/`、对应测试、启动配置与开发文档；`README.md` 分开写两条上手路径。`SKILL.md` 仅在确需调用共用能力时补接口说明，不重写摄影评价标准。现有 `assets/visual-report-template.html` 和渲染器按兼容需要复用；公共示例继续标为示例。

## 必须验证的失败路径

- 未配置模型、格式损坏／不支持、文件过大：不能收图后展示固定样例答案。
- 重复点击、刷新、取消、模型超时：不无提示地重复生成或扣费；部分完成与完整完成分开。
- 模型输出不合合同、参考无可靠匹配、改图失败：各模块显示实际状态，不伪造分数、作品链接或图片。
- 私人图片、API 密钥、本地路径：不泄漏到公开页面、日志、版本库；本地服务不默认对公网开放。
- 两种入口：相同规则来源与字段约束有回归测试，旧 Skill 安装、旧视觉报告正常。
- 真实浏览器：桌面和窄屏完成上传、点评、追问、对照、恢复与删除。测试替身通过不能代替真实模型与真实浏览器验收。

## 完成的定义

用户能够在 Codex 里用 Skill；也能够在项目工作台中，按约定配置一次运行环境后，从自己的新照片走完“上传—点评—追问—实际调整—保存／继续”。**没有第二条真实路径，双入口目标就没有完成。** GitHub 曝光、Stars 或长期学习效果不在工程完成时作保证。

## 本轮实施细化

- Python 本机服务 + 原生 HTML/CSS/JS，沿用仓库现有 Python/Pillow 基础；不要求 Node、Codex、数据库服务或云部署。只监听 `127.0.0.1`。
- 首个适配器使用 OpenAI Responses 协议的图像输入与结构化输出；模型名由用户指定，不替用户开通账号或选付费套餐。第三方兼容端点需自行验证相同协议，不宣传支持全部供应商。
- `app/server.py` 管理上传、配置、照片会话、任务与文件白名单；`core/` 管理共用规则装配、结构校验、模型适配与可逆调整；`app/static/` 实现实际工作台。
- 共用现有报告校验器，并支持“本次未找到可靠参考”的空值。旧报告和静态示例保持兼容；模板与对应测试同步更新。
- 模型密钥只在服务内存中；私有照片、会话、原图及衍生图保存在仓库外。拒绝跨站请求、目录穿越、超大／伪装图片和危险外部 URL。
- 自动化采用可注入的模拟模型传输，验证真实 HTTP 路由及流程，不在生产界面混入假点评。另用已有授权示例提供显式演示模式，模拟测试不证明模型点评正确。
- 桌面和手机浏览器检查选图、配置、错误状态、报告阅读、追问与历史。没有用户授权的真实 API 调用前，只报告工程验证，不宣称双入口目标全部验收通过。
