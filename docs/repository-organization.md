# 仓库整理与迁移记录

2026-10-19。范围：把当前主仓库、早期界面原型、研究目录、散落的标准草稿与本项目历史报告统一管理；不开发新功能，不重新评价照片，不公开私人或授权未确认的素材。

## 目标结构

- 主项目使用独立目录 `photography-coach/`，保留根目录 `SKILL.md`，不改变技能名称与相对资源路径。
- `app/`、`core/`、`references/`、`scripts/` 保持现有职责。
- `docs/archive/prototype-v0.1/` 保存早期界面源码；`docs/demo/` 继续提供当前公开示例。
- `research/archive/` 保存可公开的历史规范和研究协议，明确它们不是当前标准或新的有效评测结果。
- `.local-data/` 保存原始照片、原始评论、冻结答卷、研究运行包、第三方检出、历史个人报告、工具缓存及完整迁移清单；全部排除在 Git 之外。
- 旧 Skill、研究和报告路径必要时保留兼容符号链接。链接不是第二份仓库或数据副本。

## 迁移顺序

1. 检查 Git 状态、远端、工作树、目标目录冲突；盘点所有本项目来源和嵌套仓库。
2. 在仓库外生成迁移前清单，对每个文件计算 SHA-256，记录相对路径、大小、文件类型和符号链接目标。
3. 用同一磁盘上的目录移动保留文件和 Git 历史，不用覆盖式复制；每个旧目录都有唯一的新位置。
4. 将历史协议与原型源码归档，原始研究和报告留在忽略目录；建立旧路径的兼容链接并记录用途。
5. 逐项核对迁移前后的文件内容；检查相对图片路径、旧 Skill 入口、嵌套第三方仓库与当前仓库状态。
6. 更新 README、研究索引、开发说明、忽略规则及版本记录，增加目录／隐私边界检查。
7. 运行原有测试和新增检查。只有校验通过后才清理已被移动或已证明重复的旧实体；不删除独有文件。
8. 推送可公开的整理结果，保留既有 GitHub Releases 和标签，用新版本记录本次结构调整，不覆盖历史版本。

## 修改范围与风险控制

修改以目录、说明和相关验证为主；根技能与摄影评价规则不重写。历史原始记录尽量逐字保留，当前说明与旧记录分开。路径兼容优先使用链接，避免修改冻结答卷导致原哈希失效。

迁移不会把 `.local-data/` 变为可公开下载的样本包。公开原型的图片依赖如果没有重新审核再分发条件，只在本地使用，并明确标注；不为了让旧演示在线加载而上传研究图片。第三方仓库保留自己的 Git 历史与远端，不并入主仓库历史。

本机迁移清单保存在 `.local-data/migrations/`。如需回滚，可按清单反向移动，并先移除对应的兼容链接；不要覆盖迁移后新产生的文件，不使用强制重置。
