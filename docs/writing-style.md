# 产品文案规范

适用范围：工作台、项目首页、报告中的固定栏目与操作提示，以及当前使用说明。不批量改写历史研究记录、引用原文或已经保存的照片点评。

## 写法

1. **标题说明内容或动作。** 用“画面分析”“调整对照”“上传照片，获取点评”，不用“把为什么放回画面里”或“看懂这一张，拍好下一张”。
2. **不替用户预设情绪。** 空记录就写“还没有上传照片”，不写“第一张，从现在开始”或“还没准备好？”。
3. **不模拟人与人的陪伴。** 界面不说“我们一起看”“这张，我们接着聊”。对话入口写“继续提问”，按钮写“发送问题”。照片点评本身仍可自然解释具体观察，不必变成术语列表。
4. **用具体信息代替自我评价。** 说明能做什么、结果是什么、还缺什么；不写“真正有用”“一针见血”“不拿名作填空”等承诺或自我表扬。
5. **区分操作、状态和解释。** 按钮用动词；“处理失败”只报告状态，不暗示用户必须重新付费重试。未生成图片写“后期建议”，已生成图片写“调整对照”。
6. **保留必要信息。** 构图、影调、透视、API 等准确用语可以保留。费用确认、数据去向、取消限制、版权署名和未实现功能不能为了简洁而删掉或弱化。

## 常用称呼

| 用途 | 用词 |
|---|---|
| 保存的照片与点评 | 照片记录 |
| 未配置也能查看的案例 | 演示案例／点评示例，明确标注已有内容 |
| 对照片的观察 | 画面分析 |
| 可以继续问问题的区域 | 继续提问 |
| 已生成的修图结果 | 调整对照／试调版 |
| 没有执行的修图方案 | 后期建议 |
| 无法从图中确认的内容 | 判断限制 |

## 本次示例

| 原文 | 改为 |
|---|---|
| 这次，看看你拍的。 | 上传照片，获取点评 |
| 第一张，从现在开始。 | 还没有上传照片。 |
| 连接一次，就能开始。 | 配置 API 连接 |
| 这张，我们接着聊。 | 继续提问 |
| 我已经直接帮你调了一版 | 调整对照 |
| 不拿不相关的名作填空 | 本次未提供参考作品 |

不使用统一的“AI 味评分”。检查的是文字是否具体、是否准确、是否有助于操作。自动测试只防止上述已移除的固定文案回到当前界面，不限制模型点评的正常表达。

## 修改前后检查

- 保持页面地址、锚点、字段 ID、数据结构和交互行为不变。
- 动态状态与静态 HTML 使用相同称呼，不能只改首屏。
- 报告模板修改后重新生成公开示例；不要改动示例的评分和照片数据。
- 查看桌面与手机换行，检查按钮、空状态、配置窗口和示例页。
- 更新当前截图，避免 README 继续展示旧文案。

2026-11-09 的文案轮次保留了原有画册式版式、暖白／炭黑配色和赤陶色重点；下方检查结果只适用于当日版本。2026-11-13 起工作台与共用报告改用暗房视觉系统，见[本轮升级合同](darkroom-upgrade-20261113.md)。

## 暗房工作台的直给表达

- 先写结论或动作，再给依据：`轻提右侧脸部，左边肖像略压暗`，不用先铺垫“如何让两者建立联系”。
- 没有值得修的错误就直接说保留什么；可选试调仍标为可选，不把审美偏好包装成命令。
- 图上短标签命名位置或动作，点击展开说明；不在图下重复同一段话。完整观察与八维区间仍保留。
- `影调强度 50%` 只表示原图与真实调色文件的混合比例，不写成曝光提升、测量值或学习进步。
- “已有调色文件”“局部放大”“生成试调版”各自描述不同状态，不用一个模糊的“优化后”混称。
