## 2. 用户为什么会留下来

用户首先想确认“你看见了我拍到什么”，然后才是下一步。首次价值顺序：认出一处成立关系，点出最值得处理的一件事，让用户在图上看见依据，实际比较改动。鼓励来自具体识别。

保留已确定的完整反馈形式：全画面观察、八维评分及理由、一个重点、现场重拍动作、当前文件调整、具体作品参考及可选练习。产品改善阅读层级，不能把观察删成一句话，也不把内部审计术语直接搬到首页。

长期价值来自用户纠错后的案例、可重做的修改、以及相似照片中的进步证据。图库数量、提示词长度和模型名称不能单独证明持续付费的理由。

| 竞争假设 | 用户能感知的行为 | 反证 |
|---|---|---|
| 有位置的点评更可信 | 点击判断，看见相关物体或区域及它们的关系 | 标记错位、泛指整个画面；有标记本身不算成功 |
| 对话比一次报告更有用 | 质疑或补充目的后，得到有依据的保留或修订 | 同义复述，或者用户说什么系统就改口 |
| 真实调整更能指导行动 | 原图和仅调色版同取景比较，解释收益与损失 | 改动看不出来，或只是一律更亮、更艳 |
| 具体作品帮助理解方法 | 能指出参考图与自己照片共同的一处关系 | 只说“都是街拍”“是大师作品” |
| 记住问题促成回访 | 下一张出现相似关系时，用两张图说明变化 | 只有上传次数、签到或平均分在增长 |

[摄影眼](https://sheyingyan.com/)公开介绍点评、评分、选片和会员，其[样片说明](https://sheyingyan.com/learn/article/73)将优化图界定为教学参考。[PhotoCritique.ai](https://photocritique.ai/)也介绍评分、编辑指令和成长工具。上述设计都是待验证假设，不声称独有或已胜过竞品。

另外加入通用 AI 基线：相同生产模型、相同照片、简短通用评图提示。如果本产品主要增加冗长内容，应缩减设计；竞争价值要体现在观察、操作和复盘中。

## 3. 主动线与页面

上传自己的照片 → 首轮点评和评分 → 追问／反驳 → 实际调整对照 → 保存讨论 → 再次上传。

相关作品和小练习就近出现，用户可跳过。首轮不要求标题、EXIF 或拍摄意图。用户可以补充用途；用途改变评价目标，不改写像素事实。

| 页面／区域 | 用户看到什么 | 主要动作 |
|---|---|---|
| 首页 | 上传入口、最近讨论；新用户可先看完整公开示例 | 上传／继续，不先选课程或等级 |
| 上传确认 | 选中的照片、可处理状态、简短的数据去向说明 | 开始／更换；低清图可继续但降低细节判断范围 |
| 等待 | 上传、看片、调整、找参考的真实状态；完成部分可先看 | 返回历史记录也能继续处理，不伪造完成百分比 |
| 点评页 | 原图、具体优点、一个重点及位置，随后是全画面观察和八项分数依据 | 点位置、问一句、看调整；成立的图允许“不必大改” |
| 图片对照 | 原图／仅调色／裁切＋调色；同取景版本等比例，实际文件可下载 | 切换、放大、看改动与代价；没有必要不产生裁切版 |
| 参考卡 | 一张明确作品、作者、直达来源、对应关系和差别 | 打开原作；无展示许可只给链接；缺失可重试 |
| 讨论区 | 针对当前图的追问、更正或意图补充 | 普通输入框为主，提供“为什么”“会失去什么”等提示 |
| 我的照片 | 缩略图、最后讨论、用户选择记下的下一步 | 继续、带新图比较、下载或删除 |
| 新旧对照 | 上次问题、两张图中的位置、可见变化和未知项 | 可取消关联，改为独立评图；不同场景不强行比较能力 |

初次打开以原图为依据；调整文件准备好后才出现对应按钮。标记可关闭，不能遮住关键区域。分数和全画面观察仍在页面中，扩展的技术审计细节才折叠。新产品页面采用安静的看片空间、照片优先、少量导航；最终视觉用真实照片验收，不预先复制多邻国风格。此方案不立即改动旧报告的显示默认值。

### 非正常状态也属于产品

| 情况 | 行为 |
|---|---|
| 上传断开、文件损坏、格式不支持 | 保留输入并解释，可换文件；尚未成功点评不扣次数 |
| 只能看清整体 | 给能支持的判断，像素级结论保留未知，不阻挡用户继续 |
| 点评完成，调整或参考未完成 | 正文可读，各模块分别显示状态 |
| 调整检查未通过 | 原图和建议保留，说明本次无可靠调整图；不能用原图副本冒充 |
| 参考无匹配或链接失效 | 说明暂缺，不补一个泛泛大师主页 |
| 用户质疑或前后矛盾 | 回看图与相关判断，更正时说明改了什么并保留旧版 |
| 重复点击、刷新或重试 | 返回同一任务，不重复启动模型或计费 |
| 用户删除 | 停止待处理任务，撤销访问，删除派生图、讨论及关联记忆；第三方保留范围另据供应商说明 |

## 4. 互动反馈怎样保持可信

每张照片有一份持续讨论记录，关联原图、判断版本、画面位置、参考作品、调整文件及追问。三种反馈分别处理：

| 用户说 | 应当回应 | 要避免 |
|---|---|---|
| “这只手其实没被挡住” | 重看区域；若错认，修订事实、建议和受影响分数 | 道歉后仍沿用错误 |
| “我就是想让人显得很小” | 复核留白、尺度是否服务该方向，讲清得失 | 把意图当作表达成功的证明 |
| “我更喜欢暖一点” | 记为偏好，给可逆尝试与肤色等代价 | 把暖色自动当作更高审美分 |

首版保存用户可查看和删除的简短记录，不将所有历史聊天无限拼入模型。事实更正、表达目标、风格偏好分开；用户反驳需要核实，不能直接作为专家标签。

再次上传时，由用户选择“评新照片”或“看看上次的问题”；系统可以建议关联，但用户能解除。只有目标和关系可比时才说“有改善”。同一张图修改成功是后期改进，摄影能力迁移还需要独立新图证据。规则或模型版本改变时，不直接比较历史分数。

### 轻量成长感，不把上传变成上课

每次只邀请用户记下一件自己愿意尝试的事，例如“下次按快门前，看一下人物背后有没有线条穿过头部”。下次上传先正常看片；确有相关证据时，再用两张图展示“上次—这次”的具体变化。没有改善也说明卡在哪里，不用惩罚式提醒或虚假的升级鼓励。

首版成长记录由“试过的动作、看懂的关系、可比较的照片”组成，可跳过、修改或删除。连续使用奖励、经验值和技能树留待回访验证后；上传次数和分数上涨不冒充摄影能力。用户获得的成就感首先来自看见自己做对了什么。

## 5. 调整与参考作品

当前文件的处理以确定性的曝光、色彩、曲线、受控局部明暗和裁切为主：原图不覆盖，从完整调色版产生裁切版，保存参数和结果。每项改动说明影响的关系与停手条件，不为显得有用而强制修图。

真实后期与现场重拍分别显示。首版重拍指导可用原图标注和简单位置示意；生成式重拍构想放到后续，并明确标注“构想”，不得冒充当前文件的真实成片。

参考继续使用现有四项匹配规则：用户图的两处位置、参考图的对应位置、可迁移动作、不能照搬的差别。已有单图卡是起点，允许文本关键词驱动的外部检索；不将用户照片上传到公共搜图网站。检索设候选数量和时间预算，找不到合格结果就说明。展示图片须有具体许可；否则给作者、作品名、说明和官方链接。

## 7. 有终点的验证，而不是无限盲测

两条工作同步推进：用现有授权示例打通页面与会话，用有限新图检查可能误导人的行为。界面样品可以先交付；对外私测须通过最低检查。正式摄影质量发布继续遵守仓库既有门槛，不以私测名义宣布正式通过。

### 本轮检查范围

1. 最多 12 张开发案例，优先复用旧材料并补缺失场景；资料可见，明确称为开发检查。
2. 另冻结 8 张未参与本轮调参的新图：日常多人场景、人物与环境、城市建筑、旅行风景各 2 张。包含无需大改、适合调整及难以判断的情况，但不事先规定唯一审美答案。图片哈希、来源、权限、模型和规则版本绑定保存。
3. 回答先冻结，再查看评阅锚点。评分材料和编辑配方不进入答题输入。相同任务或模型的复核只称内部查错，不包装成独立专家认证、严格盲测或与预训练材料隔离。
4. 增加 6 组追问：事实纠正、意图补充、偏好争议各 2 组。对 4 张图各多跑一次，检查主判断是否无依据地反转。
5. 修改至多两轮。检查组一旦用于改规则就转成开发材料；如需再验，另用 8 张新图，不能在原组反复测到通过。预算不足则交付错误与收窄建议，不伪造成绩。

两轮后仍未达到底线，交付当前可用样品、阻碍和取舍：可以关闭不可靠的自动裁切或定位，保留明确限制；核心观察若持续错误则停止对外试用。不得静默追加一批又一批测试。关闭功能后，样品需明确标为能力缩减版本，不能宣称完整首版已完成。

此检查不替代现有 100 张正式发布门槛。当前旧发布证据无效的状态仍保留；仓库中的发布校验不会为了本方案变绿而降低标准。

### 质量记录与私测底线

| 记录项 | 核查方法 | 建议私测前门槛，尚非成绩 |
|---|---|---|
| 关键事实 | 主结论、动作前提、图上位置逐条核对实际图 | 8 张无改变首要建议的严重错认；争议单列，不算通过 |
| 建议可执行 | 记录动作、可得性、效果、代价 | 至少 7/8 张主要建议前提成立、能理解；不许要求原文件补回画外内容 |
| 实际调整 | 原图、处理参数、结果及局部关系逐一比较 | 已交付图无未声明内容改变；适合后期案例记录成功数／尝试数，不能靠全部不出图取得满分 |
| 参考匹配 | 具体作品、可用来源、两图机制对应及差别 | 已交付链接均可核验；8 张至少 6 张有合格匹配，并同时报告覆盖率与匹配有效率 |
| 处理反驳 | 冻结首答、追问与修订理由 | 6 组无无证据迎合；至少 5/6 能直接回应并给依据或明确未知 |

自动化负责结构、任务状态和文件一致性，不能替代实际看图。八维评分核查理由和口径，不加总成一个审美准确率。抽样无严重错误只是本轮观察，不能宣传为产品永不看错。

### 公平对照

获得账号、照片权限且符合服务条款后，才用同样图片和中性请求实测摄影眼，保留时间、费用、失败和重试。先比较各自默认完整体验，再比较共同功能；不能只挑对我们有利的字段。隐藏产品名，保留原有信息层级，允许“差不多”“都不行”。通用 AI 基线使用同模型、同图，避免把模型差异当产品优势。

本轮尚未获得摄影眼的账号、付费及用户照片外发授权，不会上传现有用户照片。拿不到竞品输出仍可验证自己的完整体验，但不得写竞品胜率。匿名用户偏好证明体验选择，不能直接证明摄影理论正确。

### 用户价值

先准备自愿试用入口和简短反馈，之后通过公开样例吸引报名；不要求项目发起人先找专家或交出更多照片。不代发招募消息。若没有真实用户，内部查错可继续，但商业验证保持未完成。

| 指标 | 分母与证据 | 初步继续投入线 |
|---|---|---|
| 看懂重点 | 至少 10 位非项目成员首次收到完整报告后，能自行指认图中的问题或保留点 | 至少 7/10；记录不理解与不同意的原因 |
| 知道下一步 | 同组用户能说出愿意尝试的具体动作及代价 | 至少 7/10；喜欢文风不能替代此项 |
| 再次使用 | 首次完成后已满 14 天、允许记录行为的同组用户 | 至少 4/10 主动上传第二张独立照片；纯刷新、修图重试不算 |
| 迁移证据 | 实际提交相关新图／复拍的用户，逐对保存可见变化与场景差异 | 先观察，不以自评上涨或少量成功个案宣称学习有效 |
| 完成率、时间与费用 | 全部已接受任务，失败也计入；记录首个有用反馈和完整结果的中位数及 P90 | 先获得分布；样例缓存速度不能当线上性能 |

这些是探索性决策线，不是行业基准或统计结论。普通用户验证理解和价值；画面复核验证依据，两者分别记录。

## 8. 产品实现顺序与数据边界

### 从现有技能接到产品

手机页面提交照片 → 服务端建立任务 → 看图与结构化点评 → 校验关键字段 → 发布可读报告；实际调整和参考检索随后补全各自模块。追问以当前照片、相关判断和必要历史为输入，再次上传时由用户确认关联。

首版采用响应式 Web 前端，建议配合 Python 服务，方便复用现有脚本。先选一个生产模型供应商并保留替换接口；使用一个任务处理进程及持久化任务记录即可。框架版本、存储和登录供应商在实施前按目标市场确认，无需先做微服务或大型向量数据库。

需要保留的最少数据：照片 ID 和原图哈希；报告及模型／规则版本；每条判断的局部位置和依据；追问与更正；调整参数、原图／仅调色／裁切版本；参考来源和核验日期；用户确认的目标；新旧图关联；逐调用费用和状态。图片、对话和偏好能一起删除，不在公开仓库保存私人记录。

模型输出编辑参数和位置建议，由受控处理器执行；不能让任意生成代码直接访问服务端文件。模板只处理经过校验的字段。密钥保留在服务端。任务重复提交使用同一身份返回已有结果，避免重复付费。

### 首批市场与模型供应商

第一市场暂按中国大陆中文用户，这是仍可修改的商业假设；确认 Web 形态不等于确认市场和供应商。规划用的 GPT-6 Astra 不自动成为生产后端。按 2026-10-14 核查的 [OpenAI API 支持地区](https://developers.openai.com/api/docs/supported-countries)，当时名单不包含中国大陆，且官方说明向名单外提供服务可能导致账户受限，实际接入前须重新核验。因此大陆产品要优先选择明确支持当地用户和部署场景的供应商，并用相同照片检验能力；不能靠替换网络出口当作解决方案。

若选择受支持地区的市场，再按对应条款与账户条件评估 OpenAI 等服务。两条路径共用产品设计和供应商适配接口。该选择只阻挡真实生产调用与上线，不阻挡本地样品和界面开发。

首批在线私测建议邀请访问、默认私密。上传前明确处理服务和期限；暂定 30 天保存原图、调整与会话，到期前可下载，具体方案在上线前确认。对外发送的分析副本默认移除位置等无关元数据；用户主动删除同步撤销本服务访问与衍生记录。供应商保留政策须具体告知，不承诺无法控制的全链路即时删除。

## 9. 收费与成本：先知道一次完整帮助花多少

用户付费获得一个完成的“照片讨论”，比按消息收费更符合体验。候选单位：一张照片的完整点评、可做的真实调整、相关作品、一组有限追问与一次复盘。免费试用也应让用户看懂价值，不用半句话或不相关大师作品诱导解锁。

早期商业验证可考虑小次数包，实际单价在成本与付费意愿数据之后决定。月订阅等到回访和使用分布稳定；不先承诺无限用。失败自动退回次数；同一次操作的技术重试不再收费。首次试用、套餐限额和改图缺失时的处理在收费前写清楚。会员功能不能改变第三方图片的许可条件。

### 单次成本账本

完整案例成本 = 初评 + 追问 + 参考检索与核验 + 图像处理 + 存储／流量 + 技术重试。

模型成本 = 未缓存输入量 × 输入单价 + 缓存读取／写入各自费用 + 输出量 × 输出单价。图像输入计费、工具返回文本与推理 tokens 都要进入相应使用量，不能只计算用户看见的文字；[官方推理说明](https://developers.openai.com/api/docs/guides/reasoning#how-reasoning-works)明确推理 tokens 按输出计费。

以下仅以 [GPT-6 Astra 标准短上下文价格](https://developers.openai.com/api/docs/pricing)作敏感性算例：每百万输入 $10、输出 $50，忽略缓存优惠，输入包含本次已计量的图像／文本，输出包含推理。不是生产报价，也不意味着大陆产品使用该 API。

| 假设的单次总量 | 输入 | 输出含推理 | 仅模型费用 |
|---|---:|---:|---:|
| 较短处理 | 8,000 | 4,000 | $0.28 |
| 较长分析／互动 | 15,000 | 15,000 | $0.90 |
| 重推理压力情形 | 40,000 | 40,000 | $2.40 |

表中总量是假设，实际 Max 调用可能更高。检索、图像处理、存储、流量、退款和失败费用需另加；币种换算使用实际结算率。摄影眼首页标示的 29.8 元／月只能作市场观察，不能据此推出我们可用同价格提供无限服务。

生产上以通过质量门槛的最低成本配置为默认；最强模型用于适用地区内的复杂图复核或品质对照。是否降档由同图结果决定，不按型号名称推断。复杂度升级、重试次数、单任务和每日总支出都设上限，并记录触发原因。

预算 B 未确定时不启动付费 API 试跑。确认预算后先跑最多 10 个完整案例，观察中位数与 P90 成本及等待时间，再决定是否扩大样本。若售价为 P、支付等比例扣费为 f、每单变量成本为 C，则贡献额为 P×(1−f)−C；固定月成本 F 的粗略回本单量为 F／贡献额，仅在贡献额为正时有意义。该算式不包含未量化的人工和获客成本，不能当利润预测。

## 10. 交付节奏与停止条件

工作量是单人配合 AI 的专注工作日估计，不是自动持续运行或固定日期承诺；从明确启动实施、具备所需服务条件时计。模型、付费和平台手续等待单独列出，不掩盖成研发耗时。

| 里程碑 | 预计投入 | 交付物及验收 | 超时或失败怎么办 |
|---|---|---|---|
| A. 可点的完整会话 | 1–2 个工作日 | 响应式 Web 页用授权样例走完上传、点评、追问、改图、参考和再次上传；所有演示回应显式标注，真实已有改图可下载；仅为过程验收 | 到期交付能看的版本与具体缺页，不先扩图库 |
| B. 一张真照片跑通 | 3–5 个工作日，需供应商与预算 | 自己选图，收到真实点评和可用调整／明确失败，刷新可恢复；记录实际成本与时间；开发案例同步查错 | 提交失败请求与费用，关闭不可靠辅助功能；核心诊断不可靠则先修核心 |
| C. 能讨论、能回来 | 2–4 个工作日 | 事实纠正、目的改变、偏好争议各有真实可复查会话；历史可恢复，一对新旧图可比较，删除有效 | 收窄复杂记忆，保住当前图讨论和主动关联，不增加课程系统 |
| D. 受控试用版（首轮交付终点） | 2–3 个工作日 | 第 7 节有限检查、手机与电脑浏览器关键路径验收、费用上限和用户隔离检查通过；可上传新照片得到真实结果、追问与保存；保留已知限制清单 | 最多两轮修订后作继续／缩范围／暂停决定，交付样品与证据，不无限续测；未满足验收不得标记首轮完成 |
| E. 用户价值观察 | 开放后 14 天起观察 | 自愿试用记录、理解度、回访、错例和成本；达到最少样本后再解释指标 | 招募不足就报告不足，不伪造留存，不自动开始收费 |

A 可先开始；B 的页面／服务结构可在选型期间准备。整体不是“先做完研究，再开始网页”的串行长项目。A–D 合计暂估 8–14 个专注工作日，实际按每阶段实物和障碍修订。付费版、公开上线和正式摄影质量认证不在这个估计内；小程序和原生 App 不在当前产品计划内。E 是后续价值验证，不将等待招募或留存观察混入首轮工程交付。

所有阶段都用任务清单明确已完成、未完成、阻塞原因。无需每个按钮重新请用户批准；阶段评审提交可操作结果，只有改变核心方向、增加真实支出或公开上线才需要关键决定。

### 样品与服务验收清单

- 附任意照片时不能悄悄展示固定样例的点评；演示数据与真实处理分开标记。
- 手机触屏与电脑浏览器均能完成上传、图片对照、追问、历史和删除；响应式布局不得遮挡判断依据或主要操作。
- 八维分数、全画面关系和首要判断齐全且不矛盾；图上位置在原图／裁切／窄屏中正确。
- 实际调色可见且解释对应；仅裁切不能声称已经调色；下载对应真实版本。
- 追问引用当前图；更正能更新受影响判断，旧版仍可追溯；不把偏好变成事实。
- 链接直达具体参考；缺失状态正常显示；参考与点评的目标一致。
- 重复提交、断线重试、刷新、模型失败有明确行为，费用不会重复累加。
- 新旧图只有确认关联才比较；删除撤销当前与派生记录访问；用户互相不可访问。

现有脚本测试作为回归基线，新功能补必要的契约及浏览器端到端检查；不为文档改写增加镜像测试。

## 11. 商业验证、需用户决定的事项

第一批获客素材是一份有权限展示的完整案例：原图、具体判断、一次有效追问、忠实调整和复拍证据。提供自愿试用入口，记录用户为何回来或离开。社区发布、招募消息和付费推广须另有明确指示，当前只准备素材。

付费意愿不能只靠“你会买吗”；真正收费前需让试用者体验完整帮助，再观察实际购买或明确拒绝的原因。少量朋友好评、GitHub 收藏、上传数量及 AI 打分均不能替代付费／复用证据。

2026-10-19 已确认：首轮建设做到 D 阶段真实可用的受控试用版；产品采用 Web 形态，不以小程序为默认后续方向。这两项不再重复征询。实施到相关边界时只需要三类决定：

1. **第一市场与生产服务**：默认大陆中文用户；如果改成受支持地区的中文用户，会改变模型、登录、存储与支付选择。
2. **真实试跑预算与账户**：供应商、可用账户和预算 B，先支持 10 个完整案例的测量；不把当前聊天订阅当作公众服务的免费后台。
3. **对外上线与商业权利**：公开范围、付费条件、产品主体及代码复用许可。开源许可证仍未确定，保持原状态；不自动用代码许可证覆盖第三方图片。

用户无需现在提供专家、补交照片或参加每一步工程决策。候选验证图先从授权来源准备；已有私人图片不外发给竞品，竞争实测的权限另行处理。

## 12. 现在的下一步

当前规划完成后，下一项实物交付应是里程碑 A：让用户在手机与电脑尺寸的 Web 页面里体验一整次照片讨论，包含一次能改变判断或说明取舍的追问。它必须有可看见的调色对照、具体参考和回访入口，不能仅换一个更漂亮的静态首页。A 仅是中间检查点，首轮完成仍以 D 阶段真实可用的受控试用版验收。

先使用现有公开授权列车示例和明确标注的会话演示；复盘可先展示一个同图调整案例，并准确叫作“后期对照”。独立新照片迁移示例需另有素材与证据，不能用同图修色冒充摄影能力提升。该样品作为工程和体验验证，不声称具备自动评图服务。

本轮没有新一轮摄影测试结果、实际用户留存或新生产服务。Web 形态与 D 阶段终点是用户已确认的决定；质量阈值、费用场景、工作量和市场方向仍为计划或假设，后续以真实记录替换。
