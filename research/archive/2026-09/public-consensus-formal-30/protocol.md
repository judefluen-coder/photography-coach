# 公开真人摄影点评盲测：30例正式协议

版本：0.1  
预注册日期：2026-09-03  
状态：在获取候选池、查看候选图片或读取入选案例标题与评论之前锁定  
基线标准：[摄影评价标准 v0.5](../../standards/photography-evaluation-standard-v0.5.md)

协议修订：A1，变更记录保留在本地原始研究的 `public-consensus-formal-30/amendment-log.md`，见[资料位置](../../../README.md#本地原始研究资料)。A1发生在正式30张锁定和评论解盲之前，只处理核心题材候选不足，不改评价门槛。

## 1. 研究问题

在用户只上传一张照片、没有先写拍摄意图时，v0.5能否：

1. 找到与公开真人重复主题相同或相邻的核心问题；
2. 对只有正向共识的照片不强制制造结构性瓶颈；
3. 在没有共识或存在冲突时表达条件、不确定性与取舍；
4. 用至少两个可定位证据支撑首要判断；
5. 给出动作、效果、代价和可得性完整的练习建议；
6. 避免编造身份、动机、器材、参数、同意状态和现场条件。

正式包验证内容对齐，不验证界面喜好、学习成效、留存或付费。

## 2. 独立样本与来源

- 只使用 RPCD 的 `test_ids.csv`；
- 永久排除10例试运行中的帖子ID和已知探索案例 `8mlk4n`；
- 不使用训练集，也不回收v0.5修订时已见过的图片；
- 帖子字段与历史公开顶层评论通过 Arctic Shift 接口核验；
- 图片必须仍由原帖子记录的直接URL访问；
- 不纳入NSFW、被标记删除、视频、动图、相册、非静态直链或最长边小于800像素的文件；
- 图片和完整评论只用于内部隔离研究，不进入可分发Skill或界面；最终成果保留来源链接、哈希、匿名主题编码和必要短摘记。

RPCD评论不能用于评价摄影者本人水平。本研究只对当前单张图片的可见关系做方法验证。

## 3. 候选池为何分为两条流

RPCD官方提供的人物检测清单约占全部帖子的一部分。若只用全局随机顺序，30例很可能无法满足产品核心的街头／旅行人文配额。因此预先建立两条互斥候选流：

1. **人物流 P**：帖子ID出现在官方 `person_ids.csv` 中，目标36个合格候选；
2. **非人物流 N**：不在人物清单中，目标24个合格候选。

人物检测只用来提高候选池中含人的比例，不作为题材真值或评分标签。误检与漏检在匿名目视分类时记录，不因照片好坏替换。

## 4. 候选池的确定性顺序

人物流对每个ID计算：

`SHA-256("photo-coach-formal30-v0.1:person:" + id)`

非人物流计算：

`SHA-256("photo-coach-formal30-v0.1:nonperson:" + id)`

各自按哈希升序筛查，依次取满36和24个合格候选。自动筛查不向盲评者显示标题、作者、自述或评论正文。

合格评论的机械条件与试运行相同：顶层、非发帖者、非机器人／版务／删除文本、去空白后不少于120字符，且至少来自3位不同评论者。网络失败只允许一次有界重试；仍失败时暂停该流，不得把瞬时错误当成样本排除理由。

## 5. 匿名题材分类

候选池只以 P001–P036、N001–N024 和图片呈现。看图后为每张指定一个主要类型；不看题名、帖子自述或评论。

| 类型代码 | 判定规则 | 正式配额 |
|---|---|---:|
| `HUMAN_CONTEXT` | 一人或多人处于公共／生活／工作／旅行环境，手势、关系或地点线索是画面意义的一部分；不以标准棚拍、单纯头像为主 | 18 |
| `PORTRAIT` | 单人或小组的摆姿、表情、面部塑形或人物呈现是主要任务 | 3 |
| `LANDSCAPE` | 自然／郊野空间、天气、尺度或路径是主要任务 | 3 |
| `ARCHITECTURE` | 建筑、室内、几何、材质或城市形态是主要任务，人物不是核心 | 2 |
| `MACRO_STILL_ANIMAL` | 微距、静物、食物、植物细节或动物特写是主要任务 | 2 |
| `CONCEPT_ABSTRACT` | 合成、观念、抽象、实验光影或难归入以上类型的形式作品 | 2 |

总计30例。类型以画面当前功能判定，不根据作者自称。若一张图跨类型，使用“删掉其中一类元素后，画面核心是否仍成立”作为主类型判断，并记录次类型。

## 6. 从候选池锁定正式样本

候选完成匿名分类后，对每个候选计算：

`SHA-256("photo-coach-formal30-v0.1:category:" + 主类型 + ":" + 帖子ID)`

每类按该哈希升序取满配额。盲评者只看到分类后的 F01–F30 与图片；帖子ID映射继续密封。

若60个候选无法填满某类：

1. 不降低配额、不改变类别定义；
2. 以同一人物／非人物流和相同哈希顺序继续取下一批12个候选；
3. 新候选同样先匿名分类；
4. 在变更日志记录扩池次数和缺少的类别。

A1补充：初始60张与第一次人物流12张扩池后，明确 `HUMAN_CONTEXT` 仍不足。为避免继续生成大量近景棚拍，新增一条环境候选流：同时满足官方人物检测、官方景别预测最大类为 `FS` 或 `LS`、且尚未进入其他候选池。该流使用独立种子 `photo-coach-formal30-v0.1:context:`，先取24个合格候选，仍只看匿名图片分类。若仍不足，每次按同一流续取12张。该修订不使用标题、评论、点赞或系统评价结果。

不得因为照片太弱、太强、太难评或系统可能不匹配而排除。

## 7. v0.5盲评输出

每张只填写以下锁定字段，不搜索参考图、不看题名／评论：

1. 主要类型与可能的次类型；
2. 画面事实；
3. 暂定解读与置信度；
4. 最成立的一点及两个位置证据；
5. 决策：`STRUCTURAL_BOTTLENECK` 或 `NO_STRUCTURAL_BOTTLENECK`；
6. 若有瓶颈：唯一首要问题、两个证据、为何优先于其他候选；
7. 若无瓶颈：一个可选实验及其不得被误解为错误的说明；
8. 重拍／重做动作、预期效果、代价和可得性；
9. 后期能做、不能做；
10. 六维0–5区间，允许N/A；
11. 未知项、替代解释与事实边界。

正式盲评不加入方法图例，以免搜索词泄露题名或反向改变诊断。图例属于Skill和界面阶段的独立验证。

## 8. 真人评论编码

解盲后把每条合格评论拆成最小主张，编码到：

- 技术可读性；
- 低层执行；
- 注意力与空间；
- 光线、曝光、色彩与影调；
- 关键关系、时机与姿态；
- 信息、意义与语境；
- 后期／重拍建议；
- 纯赞美、纯厌恶、通用建议或无画面依据；
- 条件成立和相互冲突方向。

至少两位不同评论者独立重复同一对象关系，才标重复主题。以下不能单独合并：

- “构图不好”与“光线不好”；
- “色彩太强”与“曝光太亮”；
- “焦点不对”与“整体分辨率低”；
- “我不喜欢”与具体画面问题。

正向重复主题与负向重复主题分别记录；没有负向主题不代表照片完美。

## 9. 对照标签

### 有负向重复主题

- **完全匹配**：同一对象、同一关系、影响相近；
- **部分匹配**：问题族相同，但对象、因果、范围或优先级少一层；
- **不同但有证据**：系统提出另一项有两个证据的问题，但未对齐重复主题；
- **无依据**：不可定位、违反事实或把未知当事实。

### 只有正向重复主题

- **保护成立取舍**：最成立的一点对齐，且没有强制制造破坏核心的瓶颈；
- **部分保护**：认可核心，但可选实验没有充分说明代价；
- **过度挑错**：把正向共识的核心取舍直接列为结构性瓶颈；
- **无依据**：对画面作出不可核验断言。

### 没有重复主题／有直接冲突

不进入匹配率分母，只检查是否表达不确定性、条件分支和代价。若系统武断宣布唯一方向，记为不确定性失败。

## 10. 正式门槛

| 指标 | 计算 | 门槛 |
|---|---|---:|
| 负向主题完全或部分匹配 | 有负向重复主题案例中，完全＋部分 | ≥75% |
| 负向主题完全匹配 | 有负向重复主题案例中完全匹配 | ≥40% |
| 正向主题保护率 | 只有正向重复主题中，保护＋部分保护 | ≥80% |
| 过度挑错 | 只有正向重复主题中强制瓶颈 | ≤10% |
| 证据落地 | 首要决策有至少两个位置证据 | ≥90% |
| 建议完整 | 动作、效果、代价三项齐全 | ≥90% |
| 可得性标注 | 非即时建议正确标相似场景／稀有事件并给替代练习 | ≥90% |
| 无依据事实断言 | 身份、动机、参数、器材、现场等无证据断言 | ≤5% |
| 明显不可执行建议 | 与场景、物理或伦理条件明显冲突 | ≤10% |
| 分歧表达 | 无共识／冲突案例中给出不确定性或条件分支 | ≥80% |

若有负向重复主题的有效案例少于18，或只有正向主题的案例少于3，不改变已锁定样本；报告分母不足，并在下一批独立补充样本后再判断相应门槛。

## 11. 预先定义的产品决策

- 全部门槛通过：v0.5可封装为Skill v0.1，但仍不宣称专家认证；
- 仅匹配率未通过、证据与事实边界通过：继续修优先级和类型适配，不做完整App；
- 事实错误或不可执行建议超标：暂停Skill交付，先修安全与成像约束；
- 分母不足：不宣布通过或失败，补独立样本；
- 任何情况下不删除失败案例，不用AI人设伪造真人验证。

## 12. 版权、隐私与研究结束处理

- 不公开评论者用户名；
- 结果使用主题释义和必要短摘记，不复制长篇评论；
- 没有开放许可的图片不进入Skill示例、轻量界面或最终公开包；
- 盲测完成并核验哈希后，内部图片缓存与完整评论缓存移出交付目录，只保留可追溯映射、链接、哈希和编码结果；
- 若原帖或图片已被当前用户删除，不使用归档副本重新公开。
